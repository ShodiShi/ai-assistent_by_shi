# Jarvis — локальный голосовой ассистент для Windows 10. Roadmap

Дата: 2026-09-29
Статус: согласовано с пользователем в чате, ожидает финального review этого документа.

## Цель

Полностью локальный голосовой ассистент («Джарвис») для управления ноутбуком на Windows 10:
понимает русскую речь (не только точные фразы), выполняет действия на ноуте, коротко отвечает
голосом. Никакой сервер, никакое облако — аудио, текст команд и данные не покидают ноутбук.
Работает на слабом железе без дискретной видеокарты, почти ничего не потребляет в простое и
полностью «исчезает» во время игр.

## Железо и ограничения

- Windows 10 (RU), права администратора не требуются, кроме явно отмеченных мест
  (например, установка автозапуска через Планировщик заданий).
- CPU: Intel Core i5-1335U (10 ядер / 12 потоков), только Intel Iris Xe (без дискретной видеокарты) —
  всё считается на CPU.
- ОЗУ 16 ГБ, в простое свободно ~8 ГБ.
- Все модели — бесплатные, скачиваются один раз, дальше работают офлайн.

## Архитектура: два процесса

1. **Jarvis.Guard (Go)** — работает всегда, 5-15 МБ RAM. Только лёгкие функции: определение игры,
   глобальная горячая клавиша, иконка в трее, запуск/остановка/перезапуск ядра, автозапуск
   при входе в Windows. Никаких моделей и сети.
2. **Jarvis.Core (C#, .NET 8)** — голосовой конвейер, разбор команд, инструменты, озвучка.
   Запускается сторожем; в игровом режиме завершается полностью (не просто выгружает модели).
3. **Jarvis.Settings (C#, WPF)** — отдельный маленький процесс окна настроек, открывается из
   трея и закрывается после использования. Появляется на Этапе 5.
4. **Связь Guard ↔ Core** — именованный канал (named pipe), JSON построчно. Схема — в
   `docs/ipc.md` (пишется на Этапе 3, когда появляется реальный обмен сообщениями).

Запасной вариант для Guard: если Go создаст лишнюю сложность или несовместимость с окружением,
заменить на маленький C#-проект с NativeAOT — интерфейс канала не меняется. Идём с Go, о
проблемах скажем явно, если возникнут на Этапе 3.

## Голосовой конвейер

Микрофон → wake word / push-to-talk → Whisper (STT) → разбор команды → инструмент → TTS.

- **Аудио**: NAudio, 16 кГц mono, VAD (Silero VAD через ONNX Runtime либо энергетический VAD),
  запись останавливается по паузе.
- **STT**: Whisper.net (обёртка whisper.cpp), квантованные ggml-модели, язык `ru`. Стартуем с
  модели `small`, замеряем скорость/точность на реальном железе в Этапе 2 и корректируем при
  необходимости. Initial prompt собирается из слов `apps.yaml`/`games.yaml` для улучшения
  распознавания команд. Модель грузится лениво, выгружается через N минут простоя (настраиваемо).
- **TTS**: sherpa-onnx (C# API) с русским голосом Piper/VITS (`ru_RU-*`). Ответы — 1-2 фразы,
  прерываются по «стоп» и при начале речи пользователя; собственный голос ассистента не
  распознаётся как команда (гейтинг микрофона на время озвучки).
- **Wake word**: PTT по горячей клавише — обязательный и основной способ, особенно в играх.
  Дополнительно пробуем openWakeWord (ONNX) и/или Porcupine (бесплатный AccessKey, но нужно
  подтвердить поддержку кастомных русских ключевых слов на момент реализации) как удобство поверх
  PTT. Решение и конкретная реализация — на Этапе 5, не блокирует более ранние этапы.

## Разбор команд: 4 уровня (`ICommandResolver`, общий `CommandPipeline`)

Каждый следующий уровень включается только если предыдущий не уверен. Цель — 70-80% команд
закрывать уровнями 1-2 за десятки миллисекунд.

1. **Правила** — регулярные выражения, словарь алиасов, лёгкая лемматизация русского языка,
   разбор чисел и времени.
2. **Сопоставление по смыслу** — embedding-модель `multilingual-e5-small` (ONNX, int8, ~113 МБ,
   384-мерный вектор, 100 языков) ищет ближайший образец команды из `intents/*.yaml`
   (10-20 формулировок на инструмент). Порог сходства настраивается; при низкой уверенности —
   дальше.
3. **Маленькая локальная LLM** — LLamaSharp (llama.cpp), без Ollama. Кандидат по умолчанию —
   Qwen2.5-1.5B-Instruct Q4_K_M (запасной вариант точнее — Qwen2.5-3B или Phi-4-mini),
   вывод ограничен GBNF-грамматикой/JSON-схемой: модель выбирает инструмент из списка и
   заполняет параметры, а не пишет свободный текст. При неуверенности модель обязана вернуть
   `clarify`. Модель грузится по требованию, выгружается через 1-2 минуты простоя.
4. **Уточнение и обучение** — короткий голосовой вопрос, выполнение выбора, сохранение нового
   алиаса/примера в `user_aliases.yaml`, чтобы в следующий раз хватило уровней 1-2. Неуверенная
   команда никогда не выполняется молча; рискованные команды всегда подтверждаются голосом.

`ILlmProvider` — интерфейс с `LocalLlmProvider` (LLamaSharp) и заглушкой `NullProvider`;
облачные провайдеры не реализуются, но интерфейс не должен мешать добавить их позже.

## Инструменты (`ITool`, JSON-схемы аргументов)

`open_app`, `close_app`, `open_url`/`web_search`, `system_control` (shutdown/restart/sleep/lock/
logout — необратимые действия только с голосовым подтверждением, таймер 10-30 c и отмена для
shutdown), громкость/mute, яркость, медиаклавиши, управление окнами (P/Invoke user32),
`take_screenshot`, `get_system_info`, `set_timer`/reminder, заметки, `launch_game`.

Универсального «выполнить произвольную команду в терминале» нет. Если появится `run_command` —
по умолчанию выключен, работает по белому списку, всегда требует подтверждения.

## Безопасность

- Только инструменты из белого списка; вывод модели проверяется схемой и валидатором аргументов.
- Голосовое подтверждение для выключения, перезагрузки, удаления, принудительного завершения
  процессов.
- Управлять ассистентом может только голос с микрофона (или текст в тестовом режиме уровня
  разработки) — текст с веб-страниц, из файлов и любого внешнего контента не является командой.
- Журнал действий (время, фраза, уровень разбора, инструмент, результат), ротация, без аудио,
  срок хранения настраивается.
- Никаких сетевых запросов в работе, кроме первоначальной загрузки моделей по явному действию
  пользователя (скрипт скачивания с проверкой хэшей).

## Игровой режим

Определение игры в Guard (опрос раз в 3-5 c): процесс из `games.yaml`,
`SHQueryUserNotificationState` (D3D full screen / busy / presentation), полноэкранное/borderless
окно на переднем плане (с исключениями — плееры, браузеры, презентации), процессы из
`steamapps\common` и папок лаунчеров. Ручное включение — голосом, из трея, горячей клавишей.

Вход в режим: Guard просит Core завершиться (3 c таймаут, затем kill) → все модели освобождаются
вместе с процессом → микрофон и wake word отключены → подрежимы `silent` (тишина, только трей и
горячие клавиши) и `ptt` (по горячей клавише Guard разово поднимает Core: уровни 1-2, малый
Whisper, без LLM, одна команда — и завершение) → Guard работает с приоритетом BELOW_NORMAL/IDLE и
EcoQoS, без окон/уведомлений/звуков поверх игры.

Целевые показатели в игре: Guard ~0-0.5% CPU, до 15 МБ RAM, GPU 0%, Core отсутствует в списке
процессов. Выход из режима — через 10-15 c после закрытия игры (защита от перезапусков).

Жёсткое ограничение — никакого взаимодействия с самими играми: не внедряться в процессы, не
хукать DirectX/OpenGL, не рисовать оверлеи, не эмулировать ввод в окно игры, не читать память
игровых процессов. Только системный уровень (защита от банов Vanguard/EAC/BattlEye).

## Производительность вне игр

Целевое потребление в простое — до 3-5% CPU и ~1 ГБ RAM с загруженным Whisper; embedding-модель
небольшая и резидентна; LLM грузится по требованию и выгружается через 1-2 минуты простоя.
Ориентировочные задержки (подтвердить замерами по ходу этапов): уровни 1-2 — единицы-десятки мс;
уровень 3 (LLM) — единицы секунд на короткий JSON-ответ на CPU без GPU. На батарее — экономичный
режим (меньшая модель Whisper, LLM отключена, реже опрос).

Публикация: `dotnet publish -c Release` self-contained single-file, ReadyToRun, trimming там, где
безопасно; Guard — Go-бинарник с `-ldflags "-s -w"`.

## Известные риски (подтвердить по ходу этапов, не блокируют старт)

- **Wake word на русском**: готовых русских моделей мало; Porcupine поддерживает бесплатный
  AccessKey для личного использования, но поддержка обучения кастомных русских ключевых слов не
  подтверждена — проверяется на Этапе 5. PTT остаётся обязательным независимо от результата.
- **Скорость LLM на CPU без GPU**: ожидается несколько секунд на короткий структурированный
  ответ для модели уровня 1.5-3B в Q4 — подтверждается замером на Этапе 5.
- **Скорость Whisper `small` на CPU**: ожидается быстрее реального времени для коротких команд —
  подтверждается замером на Этапе 2.

## Этапы

1. Ядро в текстовом режиме (ввод с клавиатуры), уровни 1-2, 4-5 инструментов, конфиги, логи,
   тесты на разбор фраз (50+ формулировок). Своя спека:
   `2026-09-29-jarvis-stage1-core-design.md`.
2. Голос (NAudio + VAD + Whisper.net) и озвучка (sherpa-onnx/Piper).
3. Guard на Go: трей, IPC, запуск/остановка ядра, горячие клавиши, автозапуск.
4. Игровой режим: детекция, silent/ptt, приоритет процесса, EcoQoS, `launch_game`.
5. Уровень 3 (LLM с грамматикой) и уровень 4 (уточнение/обучение алиасам), wake word, остальные
   инструменты, окно настроек, автозапуск через Guard, README.

Каждый этап получает отдельный implementation-план (через writing-plans), инструкцию запуска,
ручной чек-лист проверки и метрики (доля команд по уровням, задержка, пик памяти) перед переходом
к следующему.
